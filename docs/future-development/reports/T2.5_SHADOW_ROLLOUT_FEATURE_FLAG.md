## 1. Executive Summary

Task T2.5 completes Track 2 (SQL Parser Adapter & WASM Migration) by establishing a zero-downtime, fault-tolerant Shadow Rollout system for SQL Lineage parsing. 

An internal feature toggle (`parserEngine: 'legacy' | 'wasm' | 'shadow'`) was implemented across the state store, Web Worker host, and visual toolbar. In `shadow` mode, both `@guanmingchiu/sqlparser-ts` (WASM) and legacy `node-sql-parser` execute concurrently off the main thread. Results are compared across syntax errors, node topologies, edge connections, and column resolutions, providing structured telemetry to the browser console (`console.groupCollapsed` and `console.table`) without breaking or stalling the user interface.

If either engine encounters an uncaught runtime fault or syntax crash, the comparator automatically falls back to the healthy engine and logs the runtime fault telemetry safely.

## 2. Architecture & Implementation

### 2.1 Feature Flag Resolution & Persistence (`parserFeatureFlag.ts`)
The active parser engine preference is resolved in strict hierarchical order:
1. **URL Query Parameter:** `?parserEngine=wasm|legacy|shadow` or `?lineageParser=wasm|legacy|shadow` (enables instant URL-driven canary or CI testing).
2. **Local Storage:** `localStorage.getItem("erd-forge-parser-engine")` (persists user or developer preference across browser sessions).
3. **Default:** `"wasm"` (modern default engine).

### 2.2 Differential Comparator (`ShadowRolloutComparator.ts`)
The differential comparator analyzes the outputs of primary and shadow engines across four dimensions:
1. **Syntax Error Discrepancies:**
   - Detects when WASM succeeds on dialect-specific syntax (e.g. `QUALIFY`, `PIVOT`, `MERGE INTO`, `SELECT * EXCLUDE`) where legacy fails, categorizing it as an expected differential advantage (`level: "info"`).
   - Detects syntax regressions where primary reports errors while shadow parses cleanly (`level: "warning"`).
2. **Node Topology:** Compares case-normalized entity names and identifies missing or extra nodes across tables, CTEs, and subqueries.
3. **Edge Topology:** Maps graph edge relationships (`sourceName -> targetName`) and checks for connection count discrepancies or dropped dependencies.
4. **Column Resolution:** Compares mapped column counts for identical entities between parsers.
5. **Fault-Tolerant Execution (`executeShadowParse`):** Uses `Promise.allSettled` to isolate failures. If primary crashes with an unhandled exception, shadow's result is used as a seamless fallback so the visual canvas never blanks or crashes.

### 2.3 Store & UI Integration (`lineageStore.ts` & `LineageToolbar.tsx`)
- **State Store:** `useLineageStore` was extended with `parserEngine: ParserEngine` and `setParserEngine(engine)`.
- **Worker Host:** `lineage.worker.ts` exposes `parseSQLShadow`, executing parser diffing and telemetry extraction completely off the UI thread.
- **Visual Toolbar:** `LineageToolbar.tsx` embeds an engine selector dropdown (`Engine: WASM | Legacy | Shadow`) styled with custom chevron and brand focus rings. When `shadow` mode is active, an amber `DIFF` badge is rendered to clearly indicate that live differential telemetry is active in DevTools.
- **Dynamic Re-analysis:** When `parserEngine` is switched in the UI, `LineageTab.tsx` immediately re-triggers `handleAnalyze()`, enabling instant visual toggling between engine outputs.
