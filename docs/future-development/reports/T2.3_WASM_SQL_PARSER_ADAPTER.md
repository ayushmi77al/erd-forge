## 1. Implementation Summary

1. **WASM SQL Parser Adapter (`apps/web/src/lineage/parser/WasmSqlParserAdapter.ts`):**
   * **Idempotent Initialization:** Wrapped `initWasm()` in a memoized `initPromise` for deterministic, zero-overhead re-entry in both single-threaded and Web Worker contexts.
   * **Statement Dispatching:** Normalizes top-level Rust serde AST structures into `NormalizedStatement`:
     - `Query` &rarr; `SELECT` statements with CTEs and projection trees.
     - `CreateTable` &rarr; `CREATE_TABLE` with target schema/table identification and underlying query normalization.
     - `CreateView` &rarr; `CREATE_VIEW` with target table and subquery normalization.
     - `Insert` &rarr; `INSERT` with `targetTable` (`table`/`tableName` serde variants) and query normalization.
     - `Update` & `Delete` &rarr; `UPDATE` / `DELETE` normalizing source tables, joins, and filter predicates.
     - Fallback &rarr; `OTHER` for non-DML/DDL operations.

2. **AST Serde Normalization & Identifier Resilience:**
   * Handled Rust `serde` JSON serialization nuances between camelCase vs snake_case and nested identifier variants:
     - `extractIdentValue()`: Handles raw string, `{ value: "..." }`, `{ Identifier: { value: "..." } }`, and `{ name: { value: "..." } }`.
     - `extractIdents()`: Recursively unrolls `ObjectName`, `TableName`, and compound arrays into clean identifier string lists.
     - `parseObjectName()`: Resolves single table names, two-part schema/table (`reporting.daily_summary`), and three-part database/schema/table paths.

3. **Projection & Expression Normalization:**
   * **Wildcards:** Normalizes `Wildcard` (`*`) and `QualifiedWildcard` (`table.*`, extracting table prefix).
   * **Aliases:** Normalizes `ExprWithAlias` extracting both the alias name and underlying expression.
   * **Source Column Extraction:** Recursively walks expressions (`Identifier`, `CompoundIdentifier`, `BinaryOp`, `UnaryOp`, `Nested`, `Function`, `Case`, `Cast`, `Between`, `InList`) to harvest source column lineage references (`NormalizedColumnRef[]`).
   * **Function Argument Analysis:** Supports sqlparser-rs 0.63 argument AST schemas (`List.args`, `Unnamed.Expr`, `Named.arg`, and bare expressions).

4. **Joins, CTEs, Windowing, and Set Operations:**
   * **Joins:** Accurately decodes `join_operator` variants (`Join`, `Inner`, `Left`, `LeftOuter`, `Right`, `RightOuter`, `FullOuter`, `CrossJoin`) along with `On` binary expressions and `Using` column lists.
   * **CTEs:** Translates `with.cte_tables` and handles explicit column alias lists (e.g. `WITH MonthlySales (cust_id, revenue) AS ...`).
   * **Windowing & QUALIFY:** Preserves `qualify` expressions (Snowflake/BigQuery) and window function structures.
   * **Set Operations:** Recursively normalizes `SetOperation` (`Union`, `Intersect`, `Except`, `set_quantifier: "All"` &rarr; `UNION_ALL`).

5. **Unit & Integration Test Suite (`apps/web/tests/lineage/WasmSqlParserAdapter.test.ts`):**
   * 12 comprehensive test cases testing:
     - Metadata & idempotent initialization.
     - SELECT projections, column aliases, functions, binary expressions, wildcards, and qualified wildcards (`u.*`).
     - Scoped CTEs with explicit column alias mapping.
     - Multi-table JOINs (INNER, LEFT, RIGHT) and derived subqueries in FROM clauses.
     - QUALIFY clause in Snowflake/BigQuery dialect.
     - Set operations (UNION ALL) into `setOperations` arrays.
     - DDL (`CREATE TABLE AS SELECT`, `CREATE VIEW AS SELECT`) and DML (`INSERT INTO ... SELECT`).
     - Syntax error reporting with line, column, dialect, and message extraction.
