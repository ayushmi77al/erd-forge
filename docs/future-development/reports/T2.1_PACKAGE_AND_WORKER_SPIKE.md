## 1. Implementation Summary

1. **Dependency Installation (`apps/web/package.json`):**
   * Installed `@guanmingchiu/sqlparser-ts@0.63.0` (pinned, Apache-2.0, powered by `datafusion-sqlparser-rs` via WebAssembly).

2. **Vite Bundler Configuration (`apps/web/vite.config.ts`):**
   * Added `optimizeDeps: { exclude: ["@guanmingchiu/sqlparser-ts"] }` to ensure Vite dev server excludes the WASM package from esbuild pre-bundling.
   * Confirmed production Rollup build emits `sqlparser_rs_wasm_bg-*.wasm` (3.54 MB) and correctly links it to `lineage.worker-*.js`.

3. **Web Worker Integration (`apps/web/src/workers/lineage.worker.ts`):**
   * Implemented idempotent `ensureWasmInitialized()` calling `init()` from `@guanmingchiu/sqlparser-ts`.
   * Added `initWasm()` and `parseWasmSpike(sql: string, dialect: DialectInput)` to the Comlink-exposed `LineageWorkerAPI` without altering the existing legacy `parseSQL` interface.

4. **Automated Unit Testing (`apps/web/tests/lineage/sqlparserWasmSpike.test.ts`):**
   * **Idempotent Initialization:** Verified multiple calls to `init()` resolve cleanly.
   * **Core AST Parsing:** Verified ANSI/Generic queries parse into structured statement trees with typed AST nodes (`Query.body.Select.projection`).
   * **Multi-Dialect Verification:** Tested dialect-specific queries across:
     - PostgreSQL (`::` cast syntax)
     - BigQuery (backticked identifiers)
     - Snowflake (multi-part identifiers)
     - SQLite (`sqlite_master` catalog query)
     - DuckDB (`read_csv_auto` table function)
   * **Complex Expressions:** Validated CTE expressions (`WITH cte AS (...) SELECT ...`) and Window Functions (`RANK() OVER (...)`).
   * **Validation & Formatting:** Verified `format()` and `validate()` utility functions.
   * **Error Recovery:** Verified invalid SQL syntax (`SELECT * FROM (`) throws typed `ParserError`.
