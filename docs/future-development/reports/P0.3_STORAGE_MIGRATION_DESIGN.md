## 2. Core Decisions Formalized

### 2.1 Transactional & Idempotent Migration Protocol
* **Snapshotting:** Pre-flight extraction of legacy catalog records into in-memory JSON before touching the target database.
* **Transactional Execution:** Migration operates inside a strict `BEGIN IMMEDIATE TRANSACTION;` block.
* **Journaling:** Migration state stored directly in a SQLite table (`_migration_journal`) with `'in_progress'`, `'verified'`, and `'failed'` states, rather than relying on unreliable `localStorage` flags.
* **Integrity Checks:** Row-count comparisons across all core tables (`projects`, `entities`, `columns`), plus `PRAGMA integrity_check` and `PRAGMA foreign_key_check` before commit.
* **Rollback Safety:** Legacy IndexedDB store is kept intact and untouched as an immutable rollback source.

### 2.2 Single-Tab Lease Protocol (`erd-forge-storage-lock`)
* Addressed `opfs-sahpool` single-tab constraint via a deterministic `BroadcastChannel` protocol.
* Active tab emits heartbeats every 2,000 ms. Stale leases expire after 5,000 ms.
* Non-destructive user experience: Secondary tabs present a clear takeover prompt rather than throwing unhandled pool acquisition errors.

### 2.3 Durable Fallback Hierarchy
* **Tier 1:** `@sqlite.org/sqlite-wasm` with `opfs-sahpool` in Web Worker.
* **Tier 2:** `IndexedDBAdapter` (existing durable fallback).
* **Prohibited:** Transient in-memory database (`oo1.DB('catalog.db', 'ct')`) is banned for user catalog persistence to enforce the **Zero Silent Data Loss** rule.
