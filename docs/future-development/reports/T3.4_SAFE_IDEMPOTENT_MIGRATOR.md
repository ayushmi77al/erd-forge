## 1. Executive Summary

Task T3.4 implements `SafeStorageMigrator`, guaranteeing an automated, non-destructive, and strictly idempotent migration pipeline from legacy browser storage (IndexedDB) into the newly initialized official SQLite catalog (`opfs-sahpool` or durable fallback).

Migrating local databases in client-side applications carries inherent risks of partial writes, schema desynchronization, and silent data loss. To adhere to **Zero Silent Data Loss** (ADR-007), `SafeStorageMigrator` introduces:
1. **Pre-Migration Snapshotting:** Creates a comprehensive JSON backup snapshot of all legacy stores before writing to the target database.
2. **Atomic Batch Transactions:** Inserts all projects, entities, columns, relationships, and metadata inside a single atomic SQLite transaction.
3. **Rigorous Row-Count & Integrity Verification:** Post-insertion counts on target SQLite tables must match or exceed the snapshot counts. Any discrepancy immediately aborts the migration and marks the journal as aborted.
4. **Permanent Journaling (`_migration_journal`):** Maintains an audit record of migration timestamp, status (`completed` / `aborted`), source and target counts, and total record count.
5. **Strict Idempotency:** Subsequent invocations detect existing journal records and safely exit without duplicating rows or re-executing transactions.
6. **Non-Destructive Retention:** The source IndexedDB database is kept 100% intact as an offline fallback.

## 2. Architecture & Implementation

### 2.1 `SafeStorageMigrator.ts` (`apps/web/src/storage/SafeStorageMigrator.ts`)
- **Snapshot Generator (`createSnapshot`):**
  - Safely queries legacy stores: `projects`, `entities`, `columns`, `relationships`, `metadata`.
  - Computes `totalRecords` and exports a versioned timestamped snapshot.
  - Optionally mirrors snapshot into `localStorage` (`erd-forge-backup-indexeddb_to_sqlite_v1`) for easy recovery.
- **Transactional Batch Inserter (`migrate`):**
  - Constructs parameterized `INSERT OR REPLACE` statements for each record type matching the canonical `001_initial_schema.sql` definitions.
  - Serializes nested JSON properties (`examples`, `data_quality_rules`).
  - Executes via atomic `target.executeBatch()` or `BEGIN TRANSACTION ... COMMIT`.
- **Integrity Verifier:**
  - Queries `SELECT COUNT(*) FROM <table>` across all migrated tables.
  - Rejects if any target count is less than source count, logging structured discrepancies.
- **Journal Recorder (`_migration_journal`):**
  - Manages SQLite schema:
    ```sql
    CREATE TABLE IF NOT EXISTS _migration_journal (
      id INTEGER PRIMARY KEY AUTOINCREMENT,
      migration_id TEXT UNIQUE NOT NULL,
      status TEXT NOT NULL,
      source_counts TEXT NOT NULL,
      target_counts TEXT NOT NULL,
      total_records INTEGER NOT NULL,
      migrated_at DATETIME DEFAULT CURRENT_TIMESTAMP
    );
    ```

### 2.2 Trigger-Safe Migration Splitter (`MigrationRunner.ts`)
- Identified and resolved a critical SQLite WASM parser limitation where naive semicolon splitting breaks `CREATE TRIGGER ... BEGIN ... END;` blocks in `001_initial_schema.sql`.
- Implemented `splitSqlStatements(sql: string)` with trigger block tracking, comments stripping, and quote normalization (`'001_initial_schema'`).

### 2.3 `StorageService` Auto-Migration Integration (`storage/index.ts`)
- On startup, when OPFS SAHPool SQLite initializes:
  1. Runs `MigrationRunner.run()` to establish schema v1.
  2. Spawns `SafeStorageMigrator.migrate(indexedDbSource, targetSqlite)`.
  3. Seamlessly migrates existing legacy schemas into OPFS without blocking user interaction.
