## 1. Executive Summary

Task T3.2 transitions ERD Forge's storage adapters to the official `@sqlite.org/sqlite-wasm` worker engine and deploys a resilient two-tier storage hierarchy with durable `IndexedDBAdapter` fallback.

Previously, `OPFSSQLiteAdapter` was coupled to `wa-sqlite` and internal example code (`IDBBatchAtomicVFS.js`) operating on the main thread with brittle `@ts-expect-error` suppressions. Task T3.2 completely removes `wa-sqlite` from the codebase, routes `OPFSSQLiteAdapter` to `sqlite.worker.ts` via Comlink, and strengthens `IndexedDBAdapter` with native object stores (`projects`, `entities`, `columns`, `relationships`, `metadata`, `_migrations`, `_migration_journal`).

The storage architecture guarantees **Zero Silent Data Loss** (ADR-007):
- **Tier 1 (Preferred):** `OPFSSQLiteAdapter` using `opfs-sahpool` via Web Worker.
- **Tier 2 (Durable Fallback):** `IndexedDBAdapter` activated automatically if OPFS SAHPool is blocked (e.g. private browsing or unsupported browser APIs).
- **Volatile Memory Fallback:** Strictly rejected for catalog storage. If both tiers fail, a fatal initialization exception is thrown and an error status is displayed.

## 2. Architecture & Implementation

### 2.1 Refactored `OPFSSQLiteAdapter.ts`
- **Worker Connection:** Spawns `apps/web/src/workers/sqlite.worker.ts` as an ES module Web Worker and communicates asynchronously via Comlink. Also accepts a direct `SqliteWorkerAPI` proxy for in-process testing.
- **Clean Typing:** Completely uninstalled `wa-sqlite` and removed all `@ts-expect-error` imports.
- **Interface Support:** Implements `initialize(options)`, `query<T>()`, `execute()`, `executeBatch()`, `close()`, `isDurable()`, and `getEngineType()`.

### 2.2 Upgraded `IndexedDBAdapter.ts` (Tier 2 Durable Fallback)
- **Object Stores:** Auto-creates stores during database upgrade for `projects`, `entities`, `columns`, `relationships`, `metadata`, `_migrations`, and `_migration_journal`.
- **Query & Migration Compatibility:** Provides native handling for schema migration version checks (`SELECT MAX(version)` and `INSERT INTO _migrations`), `SELECT COUNT(*)`, and entity collections.
- **Durability Guarantee:** Returns `isDurable(): true` and `getEngineType(): "indexeddb"`.

### 2.3 `StorageService` Initialization Hierarchy (`storage/index.ts`)
- Automatically attempts Tier 1 (`OPFSSQLiteAdapter` with `allowMemoryFallback: false`).
- On failure (e.g. `Worker is not defined` or `Missing required OPFS APIs`), records `fallbackReason`, activates Tier 2 (`IndexedDBAdapter`), and logs a structured warning.
- If both Tier 1 and Tier 2 fail, throws `Fatal Storage Failure` without falling back to memory.
- Runs schema migrations on active SQLite adapter.

### 2.4 User-Facing Storage Telemetry (`StatusBar.tsx` & `uiStore.ts`)
- Added `storageStatus: StorageStatus` (`engine`, `isFallback`, `error`) to `useUIStore`.
- Initialized `storageService` on application boot in `App.tsx`.
- Integrated a live status badge in `StatusBar.tsx`:
  - 💾 `Storage: OPFS` (when OPFS SAHPool is active).
  - ⚠️ `Storage: IndexedDB` (with tooltip explaining durable fallback mode when OPFS is blocked).
  - ❌ `Storage: Error` (if storage cannot be initialized).
