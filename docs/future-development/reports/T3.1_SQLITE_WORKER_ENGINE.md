## 1. Executive Summary

Task T3.1 kickstarts **Track 3 (Official SQLite WASM & OPFS SAHPool)** by deploying the consortium-backed `@sqlite.org/sqlite-wasm` engine inside a dedicated Web Worker using Comlink.

Previously, ERD Forge relied on `wa-sqlite` with internal example code (`IDBBatchAtomicVFS.js`) operating on the main thread with `@ts-expect-error` annotations. Task T3.1 replaces this with the official `@sqlite.org/sqlite-wasm` (v3.54.1-build1) and sets up the asynchronous worker engine hosting `installOpfsSAHPoolVfs`. The worker architecture isolates all synchronous SQLite execution (`db.exec()`, statement preparation, transactional batching) completely off the UI thread and strictly enforces the **Zero Silent Data Loss** guarantee established in ADR-007.

## 2. Architecture & Implementation

### 2.1 Package Installation & Vite Configuration
- **Package Installed:** `@sqlite.org/sqlite-wasm@^3.54.1-build1` (pinned to the official SQLite consortium release).
- **Vite Optimization Exclusions:** Configured `apps/web/vite.config.ts` with `optimizeDeps.exclude: ["@guanmingchiu/sqlparser-ts", "@sqlite.org/sqlite-wasm"]` to prevent Vite from attempting pre-bundling on the WebAssembly binaries.

### 2.2 Worker Engine (`apps/web/src/workers/sqlite.worker.ts`)
The worker implements the `SqliteWorkerAPI` contract exposed via Comlink:
1. **`isOpfsAvailable(): Promise<boolean>`:** Feature-detects whether the host runtime provides `FileSystemFileHandle.prototype.createSyncAccessHandle` and `navigator.storage.getDirectory`.
2. **`init(options?: SqliteInitOptions): Promise<SqliteInitResult>`:**
   - Calls `sqlite3.installOpfsSAHPoolVfs({ name: "opfs-sahpool", clearOnInit: false })`.
   - On success, instantiates `new poolUtil.OpfsSAHPoolDb(dbName)`.
   - **Zero Silent Data Loss Enforcement:** If OPFS SAHPool is unavailable and `allowMemoryFallback` is not explicitly permitted (i.e. production execution), the worker cleanly rejects initialization with a descriptive error. This prevents silent volatile memory degradation and allows the storage service to activate durable `IndexedDBAdapter` fallback in T3.2.
3. **`query<T>(sql: string, params?: any[]): Promise<T[]>`:** Executes queries using `rowMode: 'object'` and returns typed objects across the Comlink boundary.
4. **`execute(sql: string, params?: any[]): Promise<void>`:** Executes single DDL or DML statements with parameterized bindings.
5. **`executeBatch(statements: Array<{ sql: string; params?: any[] }>): Promise<void>`:** Atomically executes multiple parameterized statements inside a single native SQLite transaction (`db.transaction()`).
6. **`close(): Promise<void>`:** Safely finalizes statements and closes the active SQLite handle.
7. **`getDiagnostics(): Promise<SqliteDiagnostics>`:** Exposes runtime inspection details (`isInitialized`, `isOpfs`, `vfsName`, `dbName`, `sqliteVersion`).
